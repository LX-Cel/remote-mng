你说目标，Agent 负责操作。

你用自然语言提出需求，Agent 调用 CLI 完成连接、传包、交互和长任务查询。命令由 Agent 掌握，你不需要记住它们。

远端保存：任务编号、原始日志、退出结果
关键区别

长任务的“执行记录”留在远端。重连后是去查同一个任务，而不是把部署命令再执行一遍。

CLI：Agent 的默认入口

Agent 调用 rmg … --json，读取结构化结果；不要求你手动输入命令。

MCP：另一种可选入口

让需要标准工具协议的宿主接入同一套能力。它不负责让任务在断线后继续。

辅助程序：远端的记录员

只在受管长任务中发挥作用；普通 SSH/Telnet 交互不要求安装它。

自然语言交互由你已有的 Agent 提供；remote-mng 提供可执行、可查询的远程能力。

这里假设远端 Linux 满足辅助程序要求，记录目录可写，系统没有强制清理任务。服务器重启、断电或记录丢失，不等于能够自动续跑。

“查得到任务”与“恢复原来的交互前台”，是两件不同的事。

它帮你省什么，又需要你付出什么。

价值集中在远程操作的连续性和可查询性。它能执行已有脚本，但不会自动理解你的部署业务。

+

带来的好处

长任务，不必一直守着连接

用 job 提交后，远端自己执行并记日志。关掉本地服务后，仍能重连查询原任务。

Agent 多次调用仍接得上

CLI 每次运行都会结束，但本地服务仍持有会话。Agent 下次按会话编号继续操作，不必每次重新登录。

Agent 读取统一的执行结果

Agent 用同一组 CLI 连接、传包、执行和读日志，并解析 JSON 结果。已有构建和部署脚本可以继续用。

少一些误判和重复执行

明确区分成功、失败、未知；远端记录保留时，同一任务编号与同一请求不会再次启动任务。

!

需要接受的限制

断线保障有明确范围

只覆盖辅助程序托管的非交互 job。普通命令和前台测试不会自动变成持久任务，旧终端也不会自动恢复。

设备要满足运行条件

长任务需要 Linux、常用 Shell 命令和可写目录。裁剪固件、登录清理策略仍要在真实设备上验证。

部署步骤与判断规则仍要配置

Agent 需要从项目资料或你补充的要求中确定：包放哪、怎么启动、哪些证据表示测试通过。工具本身不会猜这些规则。

有安装与维护成本

本地需要 Python。Windows 接入 MCP 前需独立启动服务；远端日志需管理空间，真实目标板兼容性尚待验收。

还有哪些首版边界？
  • Telnet 本身是明文协议；凭据引用和日志脱敏不会把它变成加密通道。
  • 遗留 SCP 只传普通文件，不支持目录递归、摘要读回验证或断点续传；SFTP 支持目录与摘要校验。
  • 本地日志默认每条流最多保留 64 MiB，超限会标记；远端作业日志没有自动轮转。
  • 断网时无法实时知道远端最新进度。远端重启后也不会自动重新执行任务。
  • 不是完整部署平台：首版没有自动回滚、跨设备事务、GUI 工作台或多人权限系统。

一次性短命令收益较小；Agent 频繁传包、交互、跟踪长任务时更有价值。

你交代任务，Agent 串起后续步骤。

例如：“把这次修改出包，部署到测试机，运行验证并汇报错误日志。”在已有目标配置和业务约定下，Agent 使用你的开发工具和 remote-mng 完成下面的工作。

CTP 场景

进入 CTP 前台、输入 TI 命令属于 session。前台里启动的测试不会自动变成持久 job。如果某项测试可以改成无需前台交互、并等待测试结束再退出的脚本，就可以交给 job 管理。若启动脚本只是把 CTP 拉到后台就退出，job 记录的仅是那个启动脚本。

Agent 的耗时部署调用示意

rmg job start lab --script ./deploy-and-check.sh --job-id deploy-001 --json
rmg job status lab deploy-001 --json
rmg job logs lab deploy-001 --json
前提：先安装 helper；脚本不需要人在终端里回答问题。

Agent 的交互调试调用示意

rmg session open lab --json
rmg session write SESSION_ID --data-file ./test-command.txt --newline --token CONTROL_TOKEN --json
rmg session wait SESSION_ID EXPECTED_OUTPUT --offset WRITE_CURSOR --json
Agent 保存会话编号和控制令牌；等待从本次 write 返回的 cursor 开始，避免匹配旧输出。

以上是给 Agent 的命令示意，需要替换目标、脚本和会话编号。此页面只演示原理，点击任何按钮都不会执行这些命令。

已经验证到哪一步？

你只需让 Agent 先做小范围试用：上传测试文件，提交长任务，再核对结果。
