| 真实连接与代理 | 9 | 跳板后的命令输出来自目标；文件只出现在目标根目录；跳板/目标主机密钥失败分别定位；HTTP/SOCKS5 实际握手后仍拒绝错误目标密钥；两种代理的认证成功路径保留目标身份；SSH 错误密码只尝试一次；代理认证失败不泄露凭据；TCP 拒绝前业务输入未发送 |

并发测试曾暴露“多个协程共享一个 SFTP 通道，服务端实际仍串行”的问题，已改为同一 SSH 连接上的独立 SFTP 子通道。最终 10 轮记录来自修复后的实现。早期单次开发测试的失败未计入上述最终稳定版本的 220 次结果，也未解释为网络性能收益。此前较小的 20 项集合另完成过 10 轮全通过；本表以补齐代理认证成功测试后的完整集合为准。

## 结论边界

这是确定性协议测试，不是 Agent 成功率实验。没有调用 Claude Code 模型，没有测量 Agent 首次完成率、人工介入率、token、恢复耗时或与 sshmng 的同条件差值。也没有做广域网吞吐量基准。

已验证 loopback 直连和一层标准跳板、无认证及认证成功 HTTP/SOCKS5、HTTP 认证拒绝、受控菜单分支、文件级恢复；尚未现场验证企业堡垒机、OTP、真实 CTP 前台及目标设备的 SFTP 并发容量。SCP 不新增摘要恢复能力。真实使用时仍需独立核实目标身份与业务成功标准。
