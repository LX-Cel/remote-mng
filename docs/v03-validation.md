# 0.3 验证与交付记录

日期：2026-09-13。本轮面向个人使用，CLI + Claude Skill 是 Agent 入口，本地网页用于开发者查看与有限管理；没有增加团队功能。对照的是优化方案中列出的功能差距，不是同条件的 sshmng 成功率竞赛。

## 真实发行包与 Agent

[发行包验证](distribution-v03.md) 记录实际 ZIP、摘要、平台、源码外运行、解释器隔离、独立 daemon、SSH/SFTP/Telnet、稳定 Skill 入口和回退结果。完整真实包和模拟制品测试分开报告，不以模拟版本替代真实升级结论。

[Claude Code 实测](validation-agent-v03.md) 保留失败尝试与修正后的固定场景。首轮发现本机 Claude Windows 宿主禁止独立子进程创建；前置条件未满足时，Agent 曾重复尝试管理器启动。这些失败不能从首次使用结果中删除。修正后安装流程可显式预启动管理器，Skill 对宿主限制立即报告，不转向 cmd、WMI、计划任务等绕过路线。对已预启动条件下的远端任务另行计量，不混成无条件的成功率。

个人已有的 uv 工具安装已从 0.2.0 升至 0.3.0，使用本次 wheel 和锁定的运行依赖；`setup --start-daemon` 更新受管 Claude Skill 并返回 ready。版本、Skill 完整性和本地 daemon 均检查通过，没有连接真实远端。原有配置和任务历史继续使用同一状态目录，未额外建立第二个全局入口。独立发行包则在隔离目录完成安装验证。

## 复查中修复的问题

- Windows PowerShell 5.1 稳定入口曾丢失参数中的双引号，且 `-File` 主机解析器拒绝独立 `-` 参数。管理入口改用逐项 Windows argv 序列化；Agent 稳定入口直接由 Git Bash 调用 native 程序，验证引号、尾反斜杠、中文、空参数以及 `--file -` 的 stdin。
- helper 的日志采集目录创建失败可能堵住业务打开 FIFO。采集器先打开管道，存储失败继续排空，持久标明输出不完整。
- 后台程序继承 stdout/stderr 会延迟输出关闭。现在立即保存直接脚本退出码与时间，显示 `waiting_for_output_close`；不靠关闭管道或杀死后台程序得到“完成”。
- 旧 helper 不支持存储配额。新提交在业务开始前返回明确升级要求，旧作业状态、日志与取消继续可用。
- 诊断中的异常消息曾可能包含凭据。改为递归结构化脱敏，覆盖引号、换行、分片回显和轮转边界。
- 控制令牌偶尔以 `-` 开头会被 CLI 当作选项。新令牌使用固定前缀，已有令牌验证仍兼容。
- 普通 Shell 收到 EOF 后，收尾关闭曾返回错误。现在返回明确的幂等关闭结果，不重连、不写业务输入，也不把连接关闭当成远端程序停止。
- 实测发现普通 Shell 读取了应用前台参考，并执行冗余退出步骤。Skill 现在按 Shell/应用分流参考，普通 Shell 不检查未使用的文件/helper 能力，收尾直接 close；保留目标身份核查、Shell 确认和原 ID 续查。
- 清理预览原先只绑定 helper 目录及作业证据。现在加入目标配置指纹，切换设备、认证身份或连接配置后不能沿用旧计划；测试证明被拒绝时没有发出删除命令。
- 旧 helper 和无法确认存储健康时，预检曾可能报告 job_ready。现在必须取得当前存储协议、轮转能力和各项前置条件的通过证据，才报告新作业就绪；旧作业仍可查询。

真实 Claude Code（本机模型映射）固定 10 次测试的业务与去重均通过，但 18 turn 下完整交付为 0/10。修复后两次 32 turn 跟进完成执行、关闭和归档；其中一次最终报告漏报已恢复的 CLI 参数错误，若计入报告准确性则完整交付为 1/2。Skill 已补充参数说明与恢复错误汇报要求，尚未重新做模型试验。不能把业务通过等同于完整 Agent 成功，也不报告普遍成功率。

## 网页验收

对新的隔离管理器建立真实 loopback SSH 目标和端口拒绝目标。页面验证了 TCP 失败阶段与“业务命令尚未发送”、时间戳、存储用量与 4 KiB 上限、任务退出结果、清理预览只含当前任务已受理的作业，以及从偏移 0 到实际可用偏移 8192 的轮转缺口。UI URL 的访问凭据被移出地址栏，浏览器无 console error/warning。清理 API 自动测试覆盖同源认证、拒绝注入其他 job ID、拒绝错误参数和传递计划校验。

## 仍需现场验证的边界

没有真实 CTP、企业堡垒机或嵌入式设备。未承诺任意多跳/OTP 自动处理、字节级续传、交互终端断线重接、远端重启后自动续跑或目录部署事务。后台服务应在业务脚本中按实际需求重定向标准流；脚本退出、文件传输完成和业务测试通过分别判断。

本轮没有在相同设备和模型条件下运行 sshmng，因此不报告“成功率超过 sshmng”或网络吞吐提升百分比。
