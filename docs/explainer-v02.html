REMOTE WORK, WITH A RECORD

你把任务交给 Agent，
每一步都能查看。

Claude Code 负责理解、规划和调用 CLI。remote-mng 负责连接设备、执行操作、保存记录。你用网页看进度，不需要记住一堆命令。

你负责目标，Agent 负责操作。

例如：“把这次构建的包部署到测试设备，运行测试，告诉我实际版本和结果。”

CLI 给 Agent · 网页给你
你

用自然语言交代工作

指定设备、产物、部署规则和成功条件。想看过程，就让 Claude 打开本地控制台。

AI

Claude Code + remote-mng Skill

Skill 是操作说明书：教 Agent 先检查、保存任务编号、读取结果，并在不确定时查询原记录。

点击下面的环节，查看它实际负责什么。

操作说明书

Skill 让 Agent 知道怎么用。

它告诉 Claude 该调用哪些命令、如何保存编号，以及怎样区分成功、失败和未知。Skill 不执行远程操作，也不额外授予权限。

本地构建照旧

Claude 调用你项目原有的编译和出包工具。remote-mng 接收明确的产物和执行脚本。

每次工作有一份档案

Agent 把上传、部署和测试关联到同一个 task。换个对话，也能按任务编号找回进度。

长任务在远端留记录

Linux Shell helper 保存受管 job 的状态和日志，不需要远端 Python、Node 或新增监听端口。

普通交互前台由本地进程持有连接；受管长任务由远端 helper 承载。这两种操作的断线恢复能力不同。

MCP 保留为可选入口；本项目的默认使用方式是 Agent CLI + Skill。

关键是知道：执行到了哪一步。

选择一种情况，点击“下一步”。左右分别展示本地记录与远端情况，它们不一定同步。

通用工具 · 项目配置

    

      
构建与传包
沿用现有编译和出包方式
Claude 在本地修改代码并调用项目构建工具。出包后通过 SFTP 或显式选择 SCP 传输，再核对传输结果。
本地代码 → 构建产物 → 目标设备
个人配方可以保存产物、脚本和远端路径。配方检查只核对文件并生成步骤参数，执行仍由 Agent 明确发起。

      
job · 无需交互的长操作
部署与长测试，留下远端记录
不需要在终端里回答问题、并且会等待工作结束的脚本，可用 helper 管理。连接断开后按原 job ID 查询。
部署脚本 → 等待结束 → 退出码 + 日志
如果脚本只把 CTP 放到后台就退出，job 完成仅代表启动脚本退出。CTP 是否健康、测试是否通过，仍要另行验证。

      
session · 持续交互
进入前台，再执行 TI 命令
按你的描述，前台入口可配置为下方形式。路径、参数、提示符、退出方式与业务成功条件，需要在真实设备上确认。
/opt/bmc/busybox_x 127.0.0.1 999
Agent 用 session step 把“输入一次”和“继续观察”绑定起来。本页的 TI RUN SMOKE 是演示命令，并非已经确认的 CTP 命令。

      
恢复边界
前台测试不会自动变成长 job
普通 SSH/Telnet 前台断线后，当前版本不能自动接回原终端。是否能查询或继续 CTP 内部测试，要看 CTP 自身提供的能力。
前台输入 ≠ 自动拥有远端持久作业记录
退出前台是否影响后台，也取决于真实程序的退出语义。不能直接套用演示程序的行为。

    

    
这版解决了什么
  • Agent 用 Skill 找到入口，获得一致的 CLI 结果和修复建议。
  • 操作有稳定编号与任务档案，换对话也能查询原进度。
  • 同一次前台请求超时后继续观察，减少重复输入。
  • 用网页集中查看任务、输出、时间与未知状态。
试用时仍需考虑什么
  • 受管长任务需要 Linux /proc、setsid 等 helper 条件。
  • 普通终端不能断线自动恢复；远端重启不会自动续跑脚本。
  • 普通 exec 的捕获输出在结束后可见；实时长任务选 job。
  • 本地日志保留近期内容；远端 job 日志尚未自动限额或清理。

    
验证到哪一步？
本机 Claude Code 已通过 Skill 完成受控 SSH/Telnet 部署、前台去重和跨管理进程停止的长任务查询。使用的是配置中的 glm-5.3 模型映射。Windows 本地测试 264 项通过、27 项平台跳过；WSL 291 项通过。真实 CTP 设备仍待试用，这些数据不是 Agent 成功率的统计。
