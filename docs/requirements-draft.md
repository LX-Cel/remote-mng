# remote-mng v0.1 需求与交付范围

日期：2026-09-11。状态：用户已授权实现首版；本文件取代早期分期草案。**断线后可查询长任务及轻量远端辅助程序已纳入 v0.1 必选交付。** 使用方式见 [README](../README.md)，实测记录见 [验证报告](validation.md)。

定位更新：2026-09-13。**Agent 是工具的主要调用者，CLI 是默认接入方式，MCP 是可选适配。用户向已有 Agent 用自然语言描述目标，不以学习或记忆本工具命令为使用前提。**

## 目标与用户

为 Agent 提供统一的远程操作能力：连接、执行、持续交互、传包、部署脚本、调试、日志和受管长任务。开发者使用自然语言说明目标、必要的项目约定与授权边界，由已有 Agent 规划并调用工具。核心不包含 CTP/TI、固定程序路径、固定端口或业务成功判据，也不自建聊天或模型服务。

源码编辑和本地构建沿用现有开发工具。产物生成后，通过本工具上传，再运行用户已有的部署和验证脚本；需要应用前台时，通过通用交互会话进入。

## 已确认约束

- 本地 CLI 以 Agent 调用为主；MCP 保留为可选入口，两者共享目标、会话和操作记录。
- 产品主流程不依赖人工敲命令或原始终端接管。已实现的人工接管保留为开发排障能力，不作为用户正常操作的前提。
- 本地覆盖 Windows 原生、WSL 与 Linux；首版使用 Python 3.11+。
- 远端连接同时支持 SSH、Telnet；文件传输覆盖 SFTP 和遗留 SCP。
- 允许安装轻量辅助程序，受管长任务在连接中断、本地进程关闭后仍可重新查询。
- 暂无公司测试机或脱敏记录；使用受控协议服务、真实 Linux 进程和 BusyBox 验证，并注明未验证范围。

## v0.1 交付与验收

| 能力 | 交付 | 验收依据 |
| --- | --- | --- |
| 目标配置 | 多目标别名、认证引用、编码、终端与传输入口分开 | 配置校验；SSH 主机验证；不保存明文密码字段 |
| 独立命令 | 退出码、输出、目录与环境参数、后台操作 ID | 分别处理成功、失败、超时及结果未知；不自动重放 |
| 持续交互 | SSH/Telnet 打开、增量读写、匹配、控制字符、退出配置 | 新输出游标避免匹配旧提示符；文本交互贯穿同一会话 |
| 输入控制 | Agent 按 session ID 和令牌读写；显式 claim/release、单一写入者 | 新控制权令牌使旧令牌失效；关闭原终端与释放输入权分开。原始终端接管仅作可选诊断 |
| 文件传输 | SFTP 文件/目录；遗留 SCP 文件；进度和覆盖控制 | SHA256 或明确未校验；失败不能标记成功；路径和取消测试 |
| 本地记录 | 共享 daemon、SQLite 历史、分页日志 | 多客户端复用；daemon 重启后历史可读；原终端标记断开 |
| 远端辅助程序 | 随 wheel 打包的 POSIX shell helper，按目标显式安装 | 无 Python/Node 依赖、无新监听端口；能力检查与版本输出 |
| 持久作业 | start/status/list/logs/cancel，稳定 job_id 与远端退出记录 | 断开提交连接、关闭本地 Manager 后重建并查询退出码和日志 |
| 重复提交 | 同 ID 与同请求幂等，冲突拒绝 | 请求摘要、原子创建；不确定提交不自动再次执行 |
| 取消 | 校验当前启动周期、进程身份和进程组后发送 TERM | 请求取消与实际退出分别报告；避免仅凭过时 PID 操作 |
| MCP 可选接入 | 结构化工具，与 Agent CLI 使用同一应用接口 | 官方 SDK stdio 初始化、工具枚举与真实调用；不要求用户为了使用工具而启用 MCP |
| 安装与文档 | 源码锁定依赖、wheel/sdist、示例、测试、依赖说明 | 隔离安装和入口检查；公开已知限制 |

具体测试数量与执行环境以验证报告为准。已有人工原始终端代码路径测试属于诊断能力验证，不作为主要使用方式。用户自然语言到真实设备的完整 Agent 任务完成率尚未测量。

## Agent 使用体验与验收方向

现有 CLI 已支持分层 `--help`、`--json`、非交互命令、任务/会话编号及日志游标；操作约定见 [Agent 使用指南](agent-guide.md)。Claude Code 用户可通过 `rmg skill install` 安装随工具分发的个人 Skill，在不同业务项目中自动发现或显式调用；独立项目的实际工具调用见 [Skill 验证报告](claude-skill-validation.md)。业务目标和部署规则仍由调用者提供，Skill 不自动发现设备或业务配置。

后续完善以“Agent 能否可靠完成任务”为准：给定目标配置和部署约定后，能否完成上传、执行、验证与结果汇报；能否在多次 CLI 调用间保存/找回 ID；能否在断线或证据不足时避免重复部署；能否只读取必要日志，并减少要求用户补敲命令的次数。易发现的机器接口、宿主集成和操作指引继续完善，不把命令数量当作产品完成度。

## 核心取舍

| 方案 | 适用性 | 决策 |
| --- | --- | --- |
| 完全免远端安装 | 连接、普通命令和传包；无法统一提供可靠的作业退出记录 | 保留为基础能力 |
| 基础能力 + 按需轻量 helper | 同时兼顾精简设备接入和持久作业 | **首版采用，helper 同版交付** |
| 强制常驻远端服务 | 后续复杂调度和多租户管理 | 首版无需引入监听服务与完整运行时 |

持久作业依赖 Linux `/proc`、POSIX shell、`setsid` 及经检测的常用命令。辅助程序启动的命令被分离到远端会话并写入持久文件；不要求 `nohup`、Python 或 Node。辅助程序与日志目录必须位于合适的可写存储。

本地界面退出不等于结束远端任务。Windows MCP 启动前需在独立终端先启动 daemon，以避免宿主回收子进程；Linux/WSL MCP 支持自动启动。

## 结果语义

- `session.write` 表示输入已写出；`session.wait` 表示观察到输出，两者都不直接判断业务成功。
- SSH exec 返回协议退出状态；Telnet 独立命令仅在显式 `shell=posix` 时使用受控完成标记，stdout/stderr 合并。
- 断线、静默、观察超时、缺失退出记录都不能推断作业成功；证据不足返回 `unknown`。
- 受管作业的 `job_id` 与本地操作 ID 分开。本地提交操作成功不等于远端作业已完成。
- 断线后重连查询受管作业，不自动重放最后命令，也不自动恢复原交互终端。
- `cancel_requested` 与实际退出状态分开；进程已经自行脱离受管进程组时，取消范围有限。
- 主机重启后已有持久日志仍可查询；未留下退出证据的任务标记未知，不提供重启自动续跑。
- 任务日志保存原始字节，显示按目标编码解码。`eof` 只表示已读完当前快照。

## 范围边界与后续验证

首版不包含工作流引擎、业务插件、自动回滚、多主机事务、多人权限平台、GUI、串口或远端 Windows 受管作业支持。构建和部署复用现有脚本，无需改动项目核心。

支持文本交互与终端透传；复杂全屏应用、任意多跳、全部企业认证方式和全部厂商设备不属于已经验证的兼容性。SFTP 与 SCP 能力不足会显式失败，不静默降级。Telnet 仍是明文协议。

后续试用优先收集真实设备的 shell/BusyBox 能力、认证方式、应用提示符及部署脚本差异，再以通用适配完善兼容性。没有实测证据时，不承诺现场兼容或给出未经测量的性能指标。
