# 控制台易用性设计

控制台面向使用 remote-mng 的开发者：Agent 负责日常 CLI 操作，开发者能够直接配置设备、理解执行状态，并在需要时接管调试。首页应回答三个问题：这是什么、我现在能做什么、下一步在哪里。

本文记录 0.8.0 控制台改版的设计依据与验收路径。安装包与发行制品的验证范围见 [0.8 发布说明](releases/v0.8.0.md)，不以界面设计目标替代实际验收。

## 采用的原则

- **以设备为入口。** 设备名称、地址、协议和登录方式放在一起；在设备卡片直接测试连接或打开终端，不先到另一处重新选择目标。
- **普通路径直接填写。** 密码登录直接输入用户名和密码，内部凭据引用由工具处理。私钥、系统 SSH 密钥可直接选择；环境变量与已有引用留给高级用法。
- **操作按目的命名。** 设备连接、任务与日志、终端调试、常用操作与工具设置各有入口。固定命令不是工具设置，不藏在设置页面中。
- **先给结论，再给证据。** 首先显示连接结果、失败原因和下一步建议；原始诊断、配置差异和内部标识可展开查看。
- **状态含义具体。** 保存配置不代表连接成功，历史连接成功不代表当前在线；发送命令、进程退出和业务验证分别表达。
- **当前上下文可见。** 调试时显示设备和控制者；人工接管后明确提供归还入口，不让 Agent 悄悄恢复输入。
- **高级能力逐步展开。** 跳板、代理、传包通道、提示符和 Helper 路径保留能力，但不阻挡第一次连接。空状态提供明确的第一步。

直接输入密码只简化操作，不改变密码生命周期：值仅保存在当前本地管理器内存中，配置只保存引用。管理器重启后需要补填密码；配置备份与导出不包含密码值。界面不能把这一能力描述成永久保存密码。

## 官方界面参考

以下参考于 2026-10-21 核查，用于理解交互模式，不是产品排名，也不表示两者的安全实现相同。

| 官方参考 | 参考中的模式 | 在 remote-mng 中的取舍 |
| --- | --- | --- |
| [Termius](https://www.termius.com/) | Hosts 列表、Host Details 中的地址/端口/用户名/密码，以及明确的连接动作 | 借鉴设备中心结构和集中填写；不引入云同步、Vault 或团队管理依赖 |
| [VS Code Remote SSH](https://code.visualstudio.com/docs/remote/ssh) | 引导添加并保存常用主机；连接进度与详细日志分开；持续显示当前远程主机 | 借鉴短连接路径、上下文提示和可展开证据；不要求用户理解 SSH 配置文件才能操作 |
| [Royal TS 连接配置](https://docs.royalapps.com/products/royalts/reference/connections/filetransfer.html) | 直接指定用户名密码，或选择已有凭据并就地管理 | 直接填写作为普通路径，引用复用作为高级路径；不让用户手工复制内部引用 |

## 主要路径验收

1. **第一次连接：** 空状态找到添加入口 → 填写地址和登录信息 → 确认配置摘要 → 保存后测试。密码设备不需要跳转设置、填写 JSON 或复制凭据引用。
2. **已保存设备：** 在同一张设备卡片找到测试连接、编辑和打开终端；明确显示最近测试时间，未测试时不显示在线。
3. **失败后继续：** 连接失败先显示可读原因与下一步；需要主机身份核验时，显示端点和指纹，并要求独立核对后明确保存信任。
4. **日常运行：** 从独立的常用操作入口选择设备，运行前看清目标与命令；运行后能在任务记录找到同一任务。
5. **人工调试：** 终端显示当前设备和控制权，接管与归还清晰；响应丢失只重取原请求，不再次发送命令。
6. **重启与迁移：** 密码失效时提示在设备表单补填；导出不包含密码，既有任务和作业标识仍保留。

同时保持离线、配置版本冲突检查、备份恢复、唯一输入控制者和稳定请求 ID 等既有约束。页面打开只读取本地记录，不自动探测设备、安装 Helper 或访问 GitHub。
