# remote-mng 0.4.0 — Agent 更新与可查询的恢复流程

这次更新让 Agent 通过同一个 CLI 入口维护 remote-mng，开发者可以在网页查看版本、更新进度和阻碍，不再手工串联下载、停止管理器、替换程序和安装 Skill。

## 新增能力

- **统一更新流程**：检查正式 Release，固定版本和 SHA256，提交后按原更新 ID 查询；重复使用同一计划不会重复安装。
- **独立进度页**：更新进程和状态记录独立于正在替换的管理器。CLI 等待结束不取消更新，网页可继续观察进度。
- **更新前检查**：核对活动会话、操作、候选包、Skill 完整性、兼容协议和独立进程创建能力。存在阻碍时保留原状态。
- **回退与显式恢复**：保留已验证版本和恢复材料。失败时区分“已恢复旧版”与“需要处理”，不把恢复旧版误报为升级成功。
- **uv 安装支持**：验证普通 uv tool 环境的归属和已安装文件，在环境外执行替换；缓存程序及依赖，支持离线回退。
- **Skill 与个人约定**：随包 Skill 增加更新流程；个人说明保存在托管目录外的 `~/.claude/remote-mng/USER.md`，升级不会覆盖。

## 使用

安装并开启新的 Claude Code 会话后，可以说：

> 检查 remote-mng 是否有新版，说明更新影响。更新时保留现有任务，完成后告诉我实际版本和验证结果。

首次安装、平台要求和自然语言示例见 [README](https://github.com/LX-Cel/remote-mng/blob/v0.4.0/README.md)。详细状态、恢复和安装来源限制见 [更新指南](https://github.com/LX-Cel/remote-mng/blob/v0.4.0/docs/updates.md)。

## 从 0.3.0 升级

0.3.0 没有统一 `update` 命令，需使用下载后的安装脚本或原有源码安装流程完成一次升级。之后才能使用新更新入口。Skill 文件更新后需要新开 Claude Code 会话。

更新不会自动部署远端 helper，不迁移数据库，不重新提交远端 job，也不会恢复已经断开的普通交互终端。真实设备和业务测试的成功判据仍由项目提供。

## 平台与验证

Windows 与 Linux 独立包、通用 Python wheel 均附带 SHA256。WSL 使用 Linux 包。仓库当前为私有，下载需要有访问权限的 GitHub 账号；软件未发布到 PyPI。

Windows 的某些 Agent 宿主限制独立后台进程。创建预检失败时返回阻碍，保留旧版和原管理器；这不等于自动升级已经成功，也不能靠预启动管理器保证后续更新进程具有相同权限。完整验收范围见 [0.4 验收记录](https://github.com/LX-Cel/remote-mng/blob/main/docs/v04-validation.md)。
