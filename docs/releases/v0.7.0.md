# remote-mng 0.7.0 Preview — 可配置、可接管的开发者控制台

**预发布版，继续面向个人试用。** 开发者现在可以直接在网页配置设备、诊断连接、管理交互模板和接管会话；Claude Code 继续通过 CLI + Skill 使用同一份配置和任务档案，不需要把所有操作交给 Agent，也不需要记住 CLI 参数。

## 安装和升级

1. 下载适合本机的完整离线安装器，按需带入内网：
   - Windows x86_64：[下载 EXE](https://github.com/LX-Cel/remote-mng/releases/download/v0.7.0/remote-mng-0.7.0-windows-x86_64-setup.exe)，双击运行。
   - Linux / WSL x86_64：[下载 RUN](https://github.com/LX-Cel/remote-mng/releases/download/v0.7.0/remote-mng-0.7.0-linux-x86_64-setup.run)，赋予执行权限后运行：`chmod +x ./remote-mng-0.7.0-linux-x86_64-setup.run`，再运行该文件。
2. 打开控制台：Windows 双击安装目录的 `bin/Open remote-mng.cmd`；Linux / WSL 运行 `bin/open-console.sh`。使用 Agent 时，新开 Claude Code 会话加载新版 Skill，也可以直接让它“打开 remote-mng 控制台”。

已有受管独立安装同样运行新版安装器更新，保留个人配置、任务和远端 job 引用；不要卸载后重装。活动会话、正在执行的操作或托管 Skill 修改可能阻止切换，应先查看阻碍。旧 uv/Python 环境的离线迁移暂不支持。

安装器包含程序、运行时、依赖、Skill、网页和 Linux Helper，不访问 GitHub 或软件源，不要求预装 Python、uv、GitHub CLI、curl 或 unzip。离线安装保持离线更新方式；普通总览和配置读取不查询新版，也不自动探测远端设备。Windows 与 WSL 分别安装并使用各自的路径和状态目录。Linux 包仍需满足发行清单记录的 glibc 基线。

## 本版新增

- **设备管理**：新增、编辑、复制、删除 SSH/Telnet 配置，维护密钥与凭据引用、编码、超时、传包路线、跳板和登录流程。保存前预览差异，应用时检查配置版本，实际变更自动备份。
- **连接诊断与信任接入**：明确测试连接并查看失败阶段；读取目标、跳板或传包路线的 SSH 指纹，经独立可信来源核对后保存。读取到公钥本身不代表服务器身份可信。
- **交互模板与常用操作**：管理前台进入/退出规则，明确测试模板；保存固定 `exec` / Helper `job` 命令，运行前展示目标、命令、工作目录和配置版本。网页和 CLI 使用相同模板与任务记录。
- **人工接管**：实时观察输出，明确接管输入、发送一次命令、Ctrl+C、按模板退出、调整尺寸或关闭连接。接管使旧控制凭证失效；页面断开或租约过期后，Agent 不会自动恢复输入，需明确归还。
- **任务透明度**：显示实际参数、命令、来源入口、步骤与结果证据。输入和打开会话使用稳定请求 ID，重取响应不重复发送。结果未知不会被当作成功，也不会自动重跑部署。
- **维护和恢复**：明确安装/更新 Helper、检查存储、预览并清理指定终态作业日志；管理本地日志配额，导出配置、导入与备份恢复。已有任务、会话及远端作业引用保护设备身份，防止旧 job ID 被查询到另一台设备。

操作说明见 [开发者控制台指南](https://github.com/LX-Cel/remote-mng/blob/main/docs/console.md)，完整安装与高级选项见 [安装指南](https://github.com/LX-Cel/remote-mng/blob/main/docs/distribution.md)。

## 升级前需要知道

- **临时凭据重启后失效。** 值只保存在本地管理器内存，配置、备份、导出和审计仅保存引用；重启后按原名称重新输入。环境变量读取自管理器进程，不保证与另一个终端的环境同步。本版没有持久密码保险箱。
- **新引用限制旧版回退。** 配置使用 `password_ref`、`passphrase_ref` 或登录流程 `send_ref` 后，工具会阻止回退到不支持它们的旧版本。先审查并恢复兼容配置；程序不会为回退自动删除你的配置。
- **普通会话不具备断线恢复。** 网络断开或管理器重启后需重新连接，历史输出不等于会话仍在运行。需要断线后继续查询的工作使用 Helper 持久 job，并保留原 job ID；远端重启不会自动续跑。
- **远端操作仍有实际影响。** 模板测试会发送进入命令，Ctrl+C、退出前台和关闭连接含义不同；取消受管作业不会回滚文件或其他终端。工具不是 Shell 沙箱。
- 控制台仅监听本机 loopback，访问链接带有本机访问凭证，不应分享。它不提供团队权限系统、完整 ANSI 终端模拟器或 Web IDE。

## 验证范围

发布前本地测试：Windows **910 项通过**、Linux/WSL **923 项通过**，并完成最终相关回归。另已验证真实回环 SSH/Telnet、浏览器配置与会话接管，以及原生离线首装、重复运行和官方 0.6→0.7 升级。

上述结果来自本地验证，不代表 GitHub CI 自动通过，也不代表全部 BusyBox 固件、公司认证流程或实际 CTP 测试设备已适配。发行制品的平台基线、摘要和各项验收结果以随包 `release-validation.json`、发行清单与 Release 记录为准；本地 Ubuntu 24.04 / glibc 2.39 的实验构建不能作为 Ubuntu 22.04 / glibc 2.35 兼容性的证据。
