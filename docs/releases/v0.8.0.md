# remote-mng 0.8.0 Preview — 更容易上手的开发者控制台

**预发布版，继续面向个人试用。** 本版重新设计控制台的界面和操作路径：打开页面就能找到添加设备、测试连接和终端调试，密码直接在设备表单填写。Claude Code 继续通过 CLI + Skill 使用同一管理器、配置和任务档案，日常 CLI 参数仍可交给 Agent。

## 安装和升级

下载适合本机的完整离线安装器，双击或运行即可；可在联网电脑下载后带入公司内网：

| 本机系统 | 下载与安装 |
| --- | --- |
| Windows x86_64 | [下载 EXE](https://github.com/LX-Cel/remote-mng/releases/download/v0.8.0/remote-mng-0.8.0-windows-x86_64-setup.exe)，双击运行 |
| Linux / WSL x86_64 | [下载 RUN](https://github.com/LX-Cel/remote-mng/releases/download/v0.8.0/remote-mng-0.8.0-linux-x86_64-setup.run)，赋予执行权限后运行 |

```sh
chmod +x ./remote-mng-0.8.0-linux-x86_64-setup.run
./remote-mng-0.8.0-linux-x86_64-setup.run
```

已有受管独立安装同样运行新版安装器更新，保留个人配置、任务和远端 job 引用；不要先卸载。活动会话、正在执行的操作或托管 Skill 修改可能阻止切换，应先查看并处理实际阻碍。更新后新开 Claude Code 会话加载新版 Skill。

安装器包含程序、运行时、依赖、Skill、网页和 Linux Helper，不要求预装 Python、uv、GitHub CLI、curl 或 unzip，安装时不访问 GitHub 或软件源。离线安装继续通过带入新版安装包更新。Windows 与 WSL 分别安装并使用各自的路径和状态目录；Linux 包仍需满足发行清单记录的 glibc 基线。旧 uv/Python 环境的离线迁移暂不支持。

打开控制台：Windows 双击安装目录的 `bin/Open remote-mng.cmd`，Linux / WSL 运行 `bin/open-console.sh`；也可以告诉 Claude Code：“打开 remote-mng 控制台。”

## 界面与流程变化

- **六个入口各有用途。** 工作总览、设备连接、任务与日志、终端调试、常用操作和工具设置通过左侧导航呈现。空状态告诉你下一步，常用命令有独立页面，小屏幕仍可完成配置和操作。
- **直接填写登录信息。** SSH/Telnet 用户名和密码在同一设备表单填写，不再要求先到设置创建并复制内部引用。私钥文件、系统 SSH 密钥与高级凭据引用仍可选；跳板、代理和独立传包路线按需展开。
- **保存后就能测试。** “保存并测试”先展示配置摘要，确认保存后才连接；也可只保存。在设备卡片直接测试连接、编辑或打开终端，设备多时可按名称、地址或用户名搜索。
- **先看结果，再查细节。** 连接失败先显示中文原因和处理建议；配置修改先显示可读摘要。原始诊断、完整差异和内部标识可展开查看，任务与终端保留可核对的结果证据。
- **继续与 Agent 共用状态。** 网页操作与 CLI 使用相同设备、模板、任务及会话控制。人工接管、归还控制权、稳定请求 ID、Helper 维护、配置导入导出和备份恢复均保留。

直接填写密码仅简化操作方式：**密码只保存在当前本地管理器内存中，管理器重启后需在设备表单补填。** 编辑已有设备时不回显密码，留空保留已有引用；界面说明密码当前是否可用。配置、备份、导出和审计不包含密码值。预览或取消保存不会改动内存密码，无效配置或版本冲突也不会先替换已有密码。本版不提供持久密码保险箱。

操作说明见 [开发者控制台指南](https://github.com/LX-Cel/remote-mng/blob/main/docs/console.md)，设计依据见 [控制台易用性设计](https://github.com/LX-Cel/remote-mng/blob/main/docs/console-design.md)，安装高级选项见 [安装指南](https://github.com/LX-Cel/remote-mng/blob/main/docs/distribution.md)。

## 保留的约束与已知边界

- **读取页面不会远程执行。** 打开或刷新页面只读取本地记录，不自动连接设备、安装 Helper 或联网发现版本。最近测试成功附带时间，不表示设备持续在线。
- **SSH 身份仍需核对。** 首次或变更的主机指纹需从独立可信来源核实，再明确保存信任；不会为了首次连接方便而关闭严格校验。
- **保存和发送不等于业务成功。** 保存配置不证明连接成功，发送命令不证明业务完成；任务保留实际输出、退出码及验证证据，未知结果不会自动重放。
- **人工控制仍需明确归还。** 页面断开或控制租约过期不会让 Agent 自动恢复输入。普通终端断线或管理器重启后仍需重新连接；长任务通过 Helper 原 job ID 查询，远端重启不会自动续跑。
- **升级兼容性仍检查。** 0.7 起支持的凭据引用需要兼容程序；含这些字段时，工具会阻止回退到不认识它们的版本。已有任务和远端作业引用也会保护设备身份，防止把旧 job ID 查到另一台设备。
- 控制台仅用于个人本地管理，监听本机 loopback；访问链接含本机凭证，不应分享。本版不增加团队账号、云同步或完整 ANSI 终端模拟器。

## 验证范围

本次改版的 Windows 源码测试为 **930 项通过、109 项跳过**。另完成真实浏览器的 **10 项验收**，包括取消预览不保存密码、直接密码配置、编辑留空保留密码、替换密码、设备搜索、Telnet 简单登录、常用操作和小屏幕布局；并使用本机回环 SSH/Telnet 验证连接、主机指纹与终端控制。

这些结果来自本地源码与模拟设备验证，不代表全部 BusyBox 固件、公司认证流程或实际 CTP 测试设备已适配，也不能替代发行制品自身的升级、首装和兼容性验收。安装包的平台基线、摘要及各项验收结果以随包 `release-validation.json`、发行清单与 Release 记录为准。Windows 与 Linux 的发行制品必须分别完成自己的验收；旧版验证记录不能证明新版已通过。
